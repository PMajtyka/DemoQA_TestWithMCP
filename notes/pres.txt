AI Agent + Playwright MCP (Live Execution):

Slide 3: What is Playwright MCP & How Does the Architecture Work?
Slide Content:


Model Context Protocol (MCP): An open standard connecting AI models to external tools and live environments.
Playwright MCP Server: Exposes browser automation primitives (browser_navigate, browser_click, browser_snapshot, browser_type) directly to the IDE agent.
Crucial Architectural Nuance for Java Teams:


The MCP server (Node.js) manages its own browser instance for AI exploration.
Your Java test suite still requires local Playwright Java browser binaries (mvn exec:java ... install).
Visual Suggestion: Simple architecture diagram: IntelliJ IDEA (Copilot Agent) $\leftrightarrow$ Playwright MCP Server (Node/npx) $\leftrightarrow$ Live Browser (demoqa.com) alongside a separate box: Maven / JUnit 5 $\rightarrow$ Playwright Java Binaries.
Speaker Notes:


"Under the hood, MCP acts as a standardized bridge between GitHub Copilot in agent mode and a local Node.js server running Playwright. One important architectural detail for Java engineers: the browser controlled by MCP is strictly for the AI agent's exploration. When you run mvn test later, Playwright for Java still needs its own local browser binaries installed via Maven."
Slide 4: Environment Setup in IntelliJ IDEA
Slide Content:


Tech Stack: JDK 21, Maven, Node.js, IntelliJ IDEA + GitHub Copilot (Agent Mode).
Production-Ready mcp.json Configuration:


JSON
{
  "servers": {
    "playwright": {
      "command": "npx",
      "args": [
        "-y",
        "@playwright/mcp@0.0.85",
        "--output-dir",
        "./.playwright-mcp"
      ]
    }
  }
}

Speaker Notes:


"Setting this up in IntelliJ IDEA takes less than two minutes. You define the MCP server in your configuration JSON. Notice that I am pinning a specific version—0.0.85—and explicitly passing the --output-dir flag. Why didn't I just use @latest? Let’s look at a real troubleshooting trap I hit while preparing this demo."
Slide 5: Setup Lesson Learned: Why You Should Avoid @latest
Slide Content:


The Issue: Running @playwright/mcp@latest without --output-dir can silently break server initialization.
Root Cause: When launched from IntelliJ, npx may inherit the IDE's protected installation directory (Program Files) as its working directory and fail to create .playwright-mcp (Access Denied).
The Symptom: Instead of throwing a loud error, the agent silently falls back to generating code from memory without opening a browser.
The Fix:


Pin a verified package version (@0.0.85).
Explicitly define --output-dir inside your workspace.
Exclude workspace/cache folders in Windows Defender for faster execution.
Speaker Notes:


"This is a huge time-saver if you plan to try this at work. During one of my test runs, the MCP server failed to initialize because it tried to create its .playwright-mcp folder inside the protected IntelliJ installation directory. The sneaky part? The agent didn't stop—it quietly fell back to guessing the website structure from its training data! Always pin your MCP version and set --output-dir explicitly."

Slide 12: Non-Determinism & The Agentic Feedback Loop
Slide Content:


The Test Data Challenge: DemoQA has no static test user. Across runs, the agent chose two valid engineering strategies:


Run A (Full API Lifecycle): Discovered /Account/v1/User via Swagger, created a UUID user in @BeforeEach, and deleted it in @AfterEach.
Run B (CI/CD Environment Variables): Used System.getenv("DEMOQA_USERNAME") with Assumptions.assumeTrue(...)—throwing TestAbortedException when run locally without env vars.
The Fix (Agentic Feedback Loop): Pasting the single TestAbortedException line back into chat prompted the agent to immediately refactor the test and implement createUser() via the DemoQA REST API.
Speaker Notes:


"Here is an important takeaway about LLM non-determinism. In one run, the agent automatically wrote REST API calls to create and delete a user in @BeforeEach and @AfterEach. In another run, it played it safe and used environment variables, which threw a TestAbortedException locally. All I had to do was paste that single exception line into the chat, and the agent immediately refactored the test to create users via API. You don't need a perfect prompt on try one—use the test output as a feedback loop."
Slide 13: Best Practices Checklist for QA Engineers
Slide Content:


Pin Versions & Paths: Always specify an explicit @playwright/mcp version and --output-dir in mcp.json.
Prompt Like an Architect: Define locator strategies, base class responsibilities, and assertion patterns upfront.
Mandate Live Verification: Explicitly instruct the agent to test every generated locator and flow via MCP before finishing.
Work in Stages: Map & build POMs $\rightarrow$ Audit & document $\rightarrow$ Generate & run tests.
Close the Feedback Loop: Feed stack traces and JUnit exceptions directly back to the agent, and always review git diff.
Speaker Notes:


"If you want to adopt Playwright MCP in your QA team tomorrow, follow these five rules. Treat the agent like a fast, capable mid-level engineer: give it clear architectural guardrails, force it to prove its work in a live browser, and review the final git diff just like any pull request."
